# 未解決の問題・未検証事項・仕様上の判断

## 未検証事項（テスト環境がなく実施できなかったもの）

開発環境は Mac 上の Chromium 系ブラウザ（アプリ内ブラウザ）のみで、**iPhone 実機・iOS Safari での動作は未検証**です。以下は [MANUAL_TESTS.md](MANUAL_TESTS.md) の手順で確認が必要です。

| 項目 | 状況 | 補足 |
|---|---|---|
| iPhone 実機での表示・セーフエリア・片手操作 | 未検証 | 375×812 の画面サイズとダークモードはブラウザのエミュレーションで確認済み |
| ホーム画面追加・オフライン起動・更新通知 | 未検証 | Service Worker の実装のみ。localhost では既定で無効化している |
| カメラでの JAN 読み取り | 未検証 | デコーダは合成バーコード画像（拡大・ぼかし・ノイズ・逆向き）の自動テストで合格。実物のカメラ映像（ピンぼけ・反射・曲面・暗所）での読み取り率は未測定 |
| 写真の撮影・HEIC 変換 | 未検証 | iOS Safari は HEIC を自動で JPEG として渡す想定。縮小処理は `createImageBitmap` → `<img>` のフォールバックあり |
| 共有シートでのバックアップ保存 | 未検証 | `navigator.share({files})` 非対応環境ではダウンロード＋「保存できましたか？」確認にフォールバック |
| Excel / Numbers での CSV 表示 | 未検証 | UTF-8 BOM 付き・CRLF で出力。Shift_JIS の CSV 取り込みにも対応 |
| 大量データ（商品数千件）での速度 | 未測定 | 一覧は60件ずつ段階描画。在庫は商品単位でキャッシュ |
| ストレージ容量不足時の挙動 | 自動テストなし | QuotaExceededError の検出とメッセージ表示を実装。実際に容量を埋めての確認はしていない |
| サンプル写真の見た目 | 環境依存 | 写真は絵文字をキャンバスに描画して生成。iPhone では Apple Color Emoji でカラー表示されるが、カラー絵文字フォントのない環境では淡い表示になる |

## 仕様上の判断（要件の解釈）

| 要件 | 判断 | 理由・影響 |
|---|---|---|
| 「在庫0：在庫切れ」と「警告ライン未設定：不足警告なし」 | 警告ラインがある商品の0は「在庫切れ」（赤）。警告ラインがない商品の0は「在庫0」（灰色）で警告扱いしない | 両方の要件を満たすため。要補充フィルタは警告ライン設定済みの商品のみ |
| 棚卸しの記録内容 | 差分ではなく**実数**を記録し、再計算時は実数に合わせる | 棚卸しは「その日に実際にあった数」が真実のため。過去日付の操作を後から追加すると、棚卸し以降の在庫は変わらず、棚卸しの差分が変わる（記録時の差分は参考値として保持・表示） |
| 未来日付 | 入庫日・操作日・購入日・保管日に未来日は指定不可 | 誤入力防止 |
| 数量 | 整数のみ（基本単位＝最小管理単位） | 要件どおり。0.5L などを扱う場合は単位を mL にする |
| 金額の精度 | 小数2桁まで（銭単位）。評価額は有理数で保持し表示時に四捨五入 | |
| 手動ロット指定の矛盾 | 過去日付の追加などで矛盾した場合は保存を拒否し、原因の操作日と内容を表示 | 要件「黙って変更しない」 |
| 統合復元での同名マスター | 管理区分・カテゴリ・保管場所は名前が同じなら既存に対応付ける（商品は自動統合しない） | 別端末で同じ「倉庫A」を作った場合に重複しないため |
| 削除した保管場所 | 在庫がある場所は削除不可。履歴で参照されている場所は「非表示」にして履歴を保持 | 履歴の表示を壊さないため |
| 区分切り替え時の在庫数 | 「仕事用」などを選ぶと、その区分の保管場所にある数量だけで在庫数・在庫少／在庫切れを判定し、商品全体の数は「全体 ◯」と併記 | 仕事用の在庫が切れていれば、家庭用に残っていても補充が必要と分かるようにするため。区分内に履歴のない新規商品はどの区分にも表示 |
| JANからの商品情報 | 外部の商品データベースへの自動問い合わせはせず、ボタンでGoogle検索を開くだけ | 当初仕様（外部問い合わせ不要・外部通信なし）を維持。自動入力するには商品DB（Yahoo!ショッピング API 等）の利用登録が必要 |
| 依存ライブラリ | 使用しない | 開発環境に Node.js がなく、外部ソフトのダウンロードなしで完成させるため。結果として長期保守性が高い |

## 既知の制限

- ZIP64 非対応のため、バックアップは 4GB 未満（写真 約2万枚相当）まで。
- 履歴タブは最新500件を表示（それ以前は CSV 出力で確認）。
- バーコードは JAN/EAN-13・EAN-8（UPC-A は先頭0付きの EAN-13 として扱う）のみ。QR コード等は非対応。
- 写真の並び替えは左右ボタン方式（ドラッグ並び替えは未実装）。
- iOS Safari は一定期間（約7日）使わないとサイトデータを削除する場合があります（ホーム画面に追加したアプリは対象外とされています）。必ずバックアップを併用してください。
